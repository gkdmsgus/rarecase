# 진료 절차 훈련 시뮬레이션 설계 (초안)

작성 2026-09-16. 결정: **의대생 교육용**, **실제 질환 + 절차 훈련**(진단명 맞히기가 아니라 진료 절차를 채점).
참고한 게임 구조: Quarantine Zone: The Last Check — 도구로 검사 → 증상 시트에 기록 → 처분 결정.

## 1. 무엇을 채점하는가

진단명은 부가 정보이고, 채점의 중심은 **학습자가 밟은 절차**다. 그래야 의학 검수자가 없는 상태에서도
"이 환자는 X병이다"라는 강한 주장 대신 "이 상황에서는 이 문진·진찰·검사가 필요하다"는 약한 주장만 하게 된다.

채점 항목 (케이스마다 정답 목록을 미리 확정)

| 항목 | 내용 | 놓쳤을 때 |
|---|---|---|
| 필수 문진 | 반드시 물어야 할 질문 | 목록으로 알려 줌 |
| 필수 진찰 | 반드시 해야 할 신체 진찰 | 목록으로 알려 줌 |
| 위험 신호 인지 | 케이스에 심어 둔 red flag를 보고 반응했는가 | 무엇이 위험 신호였는지 |
| 검사 적절성 | 필요한 검사를 했는가 / 불필요한 검사를 남발했는가 | 불필요 검사 목록·사유 |
| 처분 | 귀가 / 외래 / 입원 / 응급 처치 / 전과 | 정답 처분과 이유 |
| (부가) 진단 | 추정 진단 | 정답 진단 |

- 점수는 항목별로 따로 표시한다(합산 점수 하나로 뭉개지 않는다).
- 모든 항목은 케이스 데이터에 사전 확정된 목록과 대조할 뿐이다. 시스템이 추론하지 않는다(원칙 2 유지).

## 2. 진행 흐름 (스테이션)

```
환자 도착(주호소·활력징후)
  → ① 문진      질문 선택 → 답변
  → ② 신체 진찰  부위·수기 선택 → 소견
  → ③ 검사 오더  X-ray / CT / MRI / 혈액 / 심전도 …  (결과는 사전 확정)
  → ④ 처치·처분  즉시 처치 + 최종 처분 결정
  → 채점: 항목별 결과 + 놓친 것 + 근거(출처 표시)
```

- 각 단계는 되돌아갈 수 있고, 마지막 처분을 제출하면 채점이 고정된다.
- 검사에는 비용·소요 시간·방사선 피폭 가중치를 둔다. 남발하면 검사 적절성 점수가 깎인다.

## 3. 케이스 데이터 형식 (초안)

```js
{
  id: 'SC-001',
  source: 'authored-scenario',        // 'dataset-label' | 'authored-scenario'
  reviewed: false,                     // 의학 검수 여부 → 화면에 "확인 필요" 배지
  patient: { age: 34, sex: 'M', chiefComplaint: '갑작스런 흉통' },
  vitals: [...],
  history:   [{ q, a, required: true|false, redFlag: false }],
  exam:      [{ id, label, finding, required: true|false }],
  orders:    [{ id, label, result, appropriate: 'required'|'reasonable'|'low-yield', radiation: 0.1 }],
  disposition: { correct: 'emergency', options: [...], why: '...' },
  diagnosis: { correct: '...', options: [...] },
  redFlags:  [{ id, text, where: 'vitals'|'history'|'exam'|'order' }],
  citations: [{ text, verified: false }],
}
```

- `required`·`appropriate`·`disposition.correct`가 채점의 ground truth이고, 케이스를 만들 때 **먼저** 정한다(원칙 1).
- `reviewed: false`인 케이스는 화면에 미검수 표시를 단다(원칙 4·6).

## 4. 원칙 개정안 (사용자 확인 필요)

원칙 4를 "정답 라벨은 영상의학과 판독 라벨만"에서 **케이스 정답 출처 두 종류**로 넓힌다.

- **A형 dataset-label**: 공개 데이터셋의 전문가 판독 라벨. 영상 판독 케이스(RSNA 4,510건)가 여기 해당.
- **B형 authored-scenario**: 작성한 훈련 시나리오. 정답은 "절차"에 한정하고, 진단·근거 문장은 미검수 표시를 단다.

나머지 원칙(1 케이스 우선, 2 시스템은 판독하지 않음, 3 영상 표시, 5 유병률, 6 확인 필요, 7 저장소 밖 영상, 8 라이선스, 9 재식별 금지)은 그대로 둔다.

## 5. 단계 계획

| 단계 | 내용 | 결과물 |
|---|---|---|
| S1 | 케이스 형식·채점 규칙 확정, 스키마 검사·채점 로직 | `src/lib/sim-*.js`, 시험 |
| S2 | 시나리오 1개로 전체 흐름 구현(문진→진찰→검사→처분→채점) | 화면 |
| S3 | 시나리오 2~3개 추가, 위험 신호·검사 남발 채점 조정 | 케이스 데이터 |
| S4 | 풀이 기록(행동 로그) 저장, 세션 구성 | 기록 |
| S5 | 영상 판독 모드(RSNA)와 합치기 | 통합 |

## 6. 열린 문제

- 시나리오 내용은 누가 쓰는가: 지금은 미검수로 작성 → 검수자 확보 시 `reviewed: true`
- 게임 요소(시간 압박·도구 해금·오판 결과)를 어디까지 넣을지
- RSNA 자산을 별도 모드로 둘지, 게임 안 검사 단계에 넣을지(원칙 9 충돌)
